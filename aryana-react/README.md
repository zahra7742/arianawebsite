# سایت آریانا کارت (AryanaPay)

صفحه‌ی معرفی (لندینگ) آریانا کارت؛ تک‌صفحه، فارسی و راست‌چین، ساخته‌شده با **React 19** و **Vite**.

این پوشه (`aryana-react`) نسخه‌ی اصلی سایت است. پوشه‌ی کناری `../aryana` نسخه‌ی قدیمی HTML/CSS/JS است که فقط برای مقایسه نگه داشته شده و دیگر استفاده نمی‌شود.

## اجرای پروژه

**پیش‌نیاز:** Node.js نسخه‌ی ۲۰ یا بالاتر (پروژه با Node 24 تست شده است).

بار اول، داخل همین پوشه کتابخانه‌ها را نصب کنید:

```
npm install
```

### اجرا هنگام توسعه

یکی از این سه راه:

| راه | کار |
|---|---|
| دوبار کلیک روی `start.bat` | اگر لازم باشد نصب می‌کند، سرور را بالا می‌آورد و مرورگر را باز می‌کند |
| `npm run dev` در همین پوشه | سرور توسعه روی http://localhost:5173 |
| `npm run dev` در پوشه‌ی بالایی (`C:\project\aryana`) | همان، از ریشه‌ی پروژه (با `package.json` ریشه) |

با هر ذخیره‌ی فایل، صفحه خودش به‌روز می‌شود.

> فایل `index.html` را با دوبار کلیک (آدرس `file://`) باز نکنید؛ صفحه سفید می‌ماند. پروژه‌ی Vite فقط از طریق سرور اجرا می‌شود.

### دستورها

| دستور | کار |
|---|---|
| `npm run dev` | سرور توسعه |
| `npm run build` | ساخت خروجی نهایی در پوشه‌ی `dist` |
| `npm run preview` | اجرای همان خروجی نهایی روی http://localhost:4173 برای تست |
| `npm run lint` | بررسی کد با oxlint |

## ساختار پوشه‌ها

```
aryana-react/
├─ index.html              پوسته‌ی صفحه: عنوان، فونت‌ها، آیکون‌های SVG و <div id="root">
├─ start.bat               اجرای سریع با دوبار کلیک
├─ vite.config.js          تنظیمات Vite
├─ backup/                 نسخه‌های پشتیبان هیروهای قبلی (در سایت استفاده نمی‌شوند؛ هر پوشه README دارد)
├─ dist/                   خروجی build؛ با هر build **پاک و دوباره ساخته می‌شود** (چیزی را فقط این‌جا نگه ندارید)
└─ src/
   ├─ main.jsx             نقطه‌ی شروع؛ React و styles.css را لود می‌کند
   ├─ App.jsx              ترتیب بخش‌های صفحه
   ├─ styles.css           همه‌ی استایل‌ها
   ├─ components/          هر بخش صفحه یک فایل
   ├─ hooks/               رفتارهای قابل استفاده‌ی مجدد (اسکرول، درگ، …)
   ├─ data/content.js      متن‌ها و لیست‌ها
   └─ assets/photos/       تصاویر
```

## محتوا و متن‌ها

بیشتر متن‌ها در [`src/data/content.js`](src/data/content.js) هستند، به شکل لیست. کامپوننت روی لیست حلقه می‌زند، پس برای افزودن یک مورد فقط یک خط اضافه کنید:

```js
export const faqs = [
  { q: 'سوال؟', a: 'جواب.' },
  // مورد جدید را این‌جا اضافه کنید
]
```

- بین آیتم‌ها ویرگول لازم است.
- متن بین دو `'` می‌آید؛ اگر خود متن `'` داشت، دورش را با `"` ببندید.
- عنوان هر آیتم (`title`، `q`، `label`) باید در لیست خودش یکتا باشد، چون React از آن به‌عنوان کلید استفاده می‌کند.

### تصاویر

تصاویر در `src/assets/photos/` هستند و بالای کامپوننت `import` می‌شوند؛ Vite هنگام build آن‌ها را بهینه و نام‌گذاری می‌کند. برای عوض کردن یک تصویر، فایل جدید را در همین پوشه بگذارید و خط `import` را عوض کنید (یا فایل را با همان نام جایگزین کنید).

| تصویر | کجا |
|---|---|
| `hero/tehran-hero.webp` | پس‌زمینه‌ی آبی هیرو (افق تهران، برج میلاد و موج نورانی) و عکس داخل کارت وسط |
| `hero/tehran-alborz.webp` و `hero/tehran-alborz-line.webp` | بخش هدف‌های مالی: افق رنگی و همان افق به‌صورت طرح خطی بی‌رنگ (هر دو روی زمینه‌ی سفید و مات‌اند) |
| `journey/` (قاب گوشی + سه اسکرین‌شات) | بخش سه مرحله‌ای (Journey) و گوشی در AppBanner |
| `app.jpg` و `card-front.png` | عکس داخل دو کارت پهن در کارت‌های امکانات (`Features.jsx`) |
| `ft-cbi.png`، `ft-enamad.png` | فوتر و نشان «مجوز بانک مرکزی» زیر کارت‌ها |
| `logo/` | لوگو و نماد (نسخه‌ی روشن برای زمینه‌ی تیره) |

عکس‌های امکانات (`Features.jsx`) **نمونه** هستند؛ برای عوض کردن، فایل جدید را در همین پوشه بگذارید و `import` بالای فایل و فیلد `img` همان کارت را عوض کنید. برای کارت بدون عکس فقط `img` را ننویسید.

## استایل، رنگ‌ها و آیکون‌ها

همه‌ی استایل‌ها در [`src/styles.css`](src/styles.css) هستند. هر بخش با یک کامنت شروع می‌شود (مثلاً `/* Contact form */`)؛ برای پیدا کردن استایل یک بخش، اسم آن را با Ctrl+F جستجو کنید. استایل‌های بخش‌هایی که بعداً اضافه شده‌اند در انتهای فایل هستند.

### رنگ‌ها و مقادیر پایه

بالای `styles.css` در `:root` تعریف شده‌اند و همه‌جا با `var(...)` استفاده می‌شوند:

| متغیر | مقدار | کاربرد |
|---|---|---|
| `--navy` | `#1a3b66` | رنگ اصلی برند |
| `--navy-2` | `#12294a` | تیترها |
| `--blue` | `#2962a8` | لینک‌ها و حالت فعال |
| `--yellow` | `#e19c26` | طلایی برند، دکمه‌ی اصلی |
| `--muted` | `#5b6b82` | متن‌های توضیحی |
| `--bg` | `#f8f9fa` | پس‌زمینه‌ی کادرها |
| `--line` | `#d0d7dd` | خطوط و حاشیه‌ها |
| `--radius` | `16px` | گردی گوشه‌ی کادرها |

فونت‌ها (Vazirmatn برای فارسی، Poppins برای اعداد و لاتین) از Google Fonts در `index.html` لود می‌شوند.

### عرض صفحه و نقاط شکست

- عرض محتوا: `.container` با حداکثر **۱۲۴۰ پیکسل** و ۴۰ پیکسل فاصله از هر طرف (در موبایل ۱۶ پیکسل).
- نقاط شکست اصلی: `980px` (تبلت؛ بیشتر چیدمان‌ها یک‌ستونه می‌شوند)، `760px` (موبایل) و `380px` (موبایل کوچک).

### آیکون‌ها

همه‌ی آیکون‌ها در یک «اسپرایت» SVG در ابتدای `<body>` فایل `index.html` هستند، هر کدام یک `<symbol id="i-…">`. در کد با کامپوننت `Icon` استفاده می‌شوند:

```jsx
<Icon name="download" className="ic" />   // از symbol با id="i-download"
```

برای آیکون جدید، یک `<symbol id="i-اسم">` به `index.html` اضافه کنید.

## انیمیشن‌ها و اسکرول

### ظاهر شدن بخش‌ها (`useReveal`)

بخش‌هایی که در لیست `revealSel` در [`src/hooks/useReveal.js`](src/hooks/useReveal.js) هستند، هنگام رسیدن به صفحه نرم ظاهر می‌شوند. شکل حرکت در CSS است (کلاس‌های `.reveal` و `.reveal.in`). برای این‌که بخشی انیمیشن بگیرد، کلاسش را به `revealSel` اضافه کنید.

### هیرو (`Hero.jsx`)

هیرو یک صفحه‌ی کامل است که با اسکرول به صفحه‌ی دوم (سفید با سه کارت) تبدیل می‌شود. متن‌ها داخل خود کامپوننت‌اند و عکس‌ها از `PHOTOS` بالای فایل خوانده می‌شوند. بر پایه‌ی **GSAP ScrollTrigger** است و دو حالت دارد که با عرض صفحه (۷۶۰ پیکسل) خودکار انتخاب می‌شوند.

**دسکتاپ (بیشتر از ۷۶۰px، با انیمیشن)**

- هیرو یک صفحه‌ی کامل (`100svh`) است و ۷۳ پیکسل بالایش **زیر هدر** می‌رود (`.rv-wrap { margin-top: -73px }`). هدر روی آن شفاف است، پس عکس تا بالاترین لبه ادامه دارد.
- ScrollTrigger هیرو را به اندازه‌ی ۳ برابر ارتفاع صفحه ثابت نگه می‌دارد (`end` در `Hero.jsx`). `scrub: 0.8` حرکت را به اسکرول وصل می‌کند و `snap` (با `directional: true`) بعد از یک اسکرول کوتاه، انیمیشن را خودکار تا آخر (یا تا اول) می‌برد.
- مراحل تایم‌لاین: متن هیرو بالا می‌رود و محو می‌شود ← عکس آبی با `clip-path` به قاب کارت بزرگ کوچک می‌شود (گوشه‌ها از همان ابتدا با شعاع ثابت ۲۲px) ← عکس و کارت با هم بالا می‌آیند و در کارت وسط می‌نشینند ← عنوان، دکمه و دو کارت کناری وارد می‌شوند.
- `clip-path` با سه مقدار پیشرفت (`a`، `b`، `rad`) و تابع `paint()` مقدار می‌گیرد، نه با انیمیت مستقیم رشته‌ی `clip-path`؛ تا شعاع گوشه مستقل از حرکت لبه‌ها بالا برود.
- **جای کارت بزرگ** در تابع `heroRect` محاسبه می‌شود: اندازه `۰٫۶۴ × ارتفاع قابل‌استفاده` (حداکثر ۲۸٪ عرض صفحه)، کمی چپ‌تر از وسط (`cx` تا ۴۶٪ عرض، با ۴۰px فاصله از عنوان) و کمی پایین‌تر از مرکز عمودی (`+ ۶٪` ارتفاع). برای جابه‌جایی یا تغییر اندازه فقط همین ضرایب را عوض کنید.
- **هدر و هیرو:** تا وقتی هیرو ثابت است، هدر شفاف می‌ماند (صفت `data-hero-pinned` روی `<html>`) و رنگ متنش سفید است تا عکس زیرش لبه‌ی بالایش را می‌پوشاند (`data-hero-covers`)؛ بعد با fade کوتاه تیره می‌شود. بعد از پایان هیرو، هدر سفیدِ blurدار عادی می‌شود. منطق سمت هدر در `Header.jsx` و رنگ‌ها در `.site-header.on-hero` و `html[data-hero-pinned] .site-header` (CSS) است.
- **کارت بانکی** (`BankCard`): کارت سرمه‌ای عمودی با CSS ساخته شده (لوگو، تراشه، شماره، تاریخ)، نه عکس. همه‌ی اندازه‌هایش با `cqw` (درصد عرض قاب) است و کل قاب را می‌پوشاند.
- **نور جاری روی موج** (`WaveGlow`): دو مسیر SVG (`WAVE` طلایی و `WAVE_B` سفید-آبی) روی موج‌های خود عکس کشیده شده‌اند و چند پرتو نور (`stroke-dasharray` انیمیت‌شده) در طولشان حرکت می‌کند. SVG با `preserveAspectRatio="xMinYMid slice"` هم‌اندازه با عکس (`object-fit: cover` و `object-position: 0% 50%`) می‌ماند. **اگر عکس هیرو را عوض کنید، این دو مسیر باید دوباره روی موج عکس جدید کشیده شوند.**

**موبایل (۷۶۰px و کمتر)**

- انیمیشن اسکرولی و ثابت ماندن وجود ندارد؛ کلاس `rv-static` (همان حالت «کاهش حرکت») اعمال می‌شود: صفحه‌ی اول عکس + متن + کارت بزرگ ثابت، و زیرش بخش دوم.
- **هدر:** چون عکس زیر هدر نمی‌رود، بالای صفحه هدر آبی یکدست است (`#2369c5`، گوشه‌ی بالا-چپ عکس هیرو؛ در `.site-header.on-hero`) و با اسکرول سفید می‌شود.
- **کارت بزرگ** (`.rv-hero-card`) تقریباً تمام‌عرض است (۱۲px فاصله از هر طرف) و زیر دکمه قرار می‌گیرد؛ پایین متن در جاوااسکریپت اندازه‌گیری و به CSS داده می‌شود (`--copy-b`).
- **سه کارت** به‌صورت **حلقه**: کارت وسط بزرگ، دو کارت کناری کوچک و کم‌رنگ با نواری باریک از آن‌ها در لبه‌ی صفحه. هر ۳٫۲ ثانیه (`setInterval` در `Hero.jsx`) هر کارت به جای بعدی می‌رود. با کشیدن انگشت هم می‌چرخد. جابه‌جایی فقط با `transform` است (`startLive` / `step` / `stopLive`).
- **چیدمان سه‌تایی در همه‌ی لحظه‌ها:** کارتی که باید از یک سر به سر دیگر برود از پشت بقیه رد **نمی‌شود** (این باعث می‌شد وسط چرخش دو کارت بزرگ با یک کارت کم‌رنگ پشتشان دیده شود). این کارت از لبه‌ی خودش بیرون می‌رود و یک **کپی** از آن (`copies` در `step`) هم‌زمان از لبه‌ی مقابل وارد می‌شود؛ در پایان چرخش کپی برداشته می‌شود و کارت واقعی جای آن می‌نشیند. کارت ورودی زودتر می‌رسد و کارت خروجی دیرتر می‌رود (`power2.out` / `power2.in`) تا هیچ‌وقت یکی از دو لبه‌ی صفحه خالی نماند.

**کاهش حرکت:** هیرو با چیدمان ثابت `rv-static` (صفحه‌ی اول، زیرش صفحه‌ی دوم)، بدون ثابت ماندن، بدون چرخش کارت‌ها و با نور موجِ خاموش نمایش داده می‌شود.

**نکته‌های فنی**

- `HEADER_H = 73` در `Hero.jsx` ارتفاع هدر است؛ اگر ارتفاع هدر عوض شد، این عدد و `73px`های بخش `.rv` در CSS را عوض کنید.
- دور بخش ثابت یک `div.rv-wrap` هست که نباید حذف شود (GSAP `pin-spacer` را داخل آن می‌گذارد).
- پاک‌سازی (ScrollTrigger، شنونده‌ها، صفت‌های `data-hero-*`) در `useLayoutEffect` انجام می‌شود و با عوض شدن حالت (کوچک/بزرگ شدن پنجره) دوباره ساخته می‌شود.
- پیش از این، هیروی قبلی و هیروی متحرک دوم در `backup/` نگه داشته شده‌اند.

### هدف‌های مالی (`Goals.jsx`)

عکس تمام‌عرض افق تهران با تیتر «زندگی، همراه با هدف‌هایتان»، توضیح، دکمه و کارت بانکی شناور. عکس از یک **طرح خطی بی‌رنگ** شروع می‌شود و رنگ می‌گیرد؛ متن‌ها و کارت یکی‌یکی وارد می‌شوند. همه‌ی ترتیب‌ها در یک تایم‌لاین GSAP هستند.

- **دسکتاپ:** بخش با ScrollTrigger ثابت می‌ماند (`pin`) و تایم‌لاین با اسکرول جلو می‌رود (`scrub`)، به طول `window.innerHeight * 2.4`.
- **موبایل (۷۶۰px و کمتر):** اسکرول ثابتی ندارد. وقتی بخش به ۸۸٪ پایین صفحه برسد، همان تایم‌لاین **خودش و بر پایه‌ی زمان** پخش می‌شود و هر بار که دوباره به بخش برسید از اول پخش می‌شود. زمان‌بندی هر عنصر در شیء `t` داخل `Goals.jsx` است (یک ستون برای موبایل، یک ستون برای دسکتاپ): تیتر و جمله‌ی بعدش تقریباً بلافاصله می‌آیند، بعد نکته، دکمه و در آخر کارت.
- **رنگی شدن:** دو عکس (رنگی و خطی) هر دو **مات** و با زمینه‌ی سفیدند. عکس رنگی زیر و با قدرت کامل می‌ماند و فقط طرح خطی روی آن محو می‌شود؛ اگر هر دو هم‌زمان محو شوند، وسط کار زمینه‌ی سفید دیده می‌شود و تصویر رنگ‌پریده می‌شود. روی این دو عکس هیچ `transition` در CSS نگذارید، با انیمیشن GSAP درگیر می‌شود.
- **موبایل، چیدمان:** متن‌ها با `top: -50px` (در موبایل‌های کوتاه‌تر از ۶۴۰px فقط `-30px`) کمی بالاتر از جای عادی‌اند (فقط جابه‌جایی ظاهری؛ کارت و بقیه جابه‌جا نمی‌شوند)، رنگ تیتر کمی روشن‌تر است و کارت ۲۸px پایین‌تر. همه در انتهای بخش `.gl` در `styles.css`.
- مبلغ‌ها و هدف‌های نشان‌داده‌شده نمونه‌اند (کامنت بالای `GOALS`).

### کارت‌های امکانات (`Features.jsx`)

چهار کارت روشن در دو ردیف: ردیف اول یک کارت پهن و یک کارت باریک، ردیف دوم برعکس. هر کارت یک آیکون در مربع سرمه‌ای، عنوان با خط طلایی و یک جمله دارد؛ دو کارت پهن («مدیریت از اپلیکیشن» و «پرداخت و خرید آسان») عکسی دارند که در رنگ کارت محو می‌شود. متن‌ها، آیکون‌ها و عکس‌ها در آرایه‌ی `CARDS` بالای فایل‌اند، نه در `content.js`.

- **ترتیب آرایه** همان ترتیب کارت‌ها در موبایل است و طوری چیده شده که کارت‌های عکس‌دار و بی‌عکس یک‌درمیان باشند (`a`، `b`، `d`، `c`). جای کارت‌ها در دسکتاپ جدا و با `grid-column` و `grid-row` روی `.rsn-slot.a` تا `.d` تعیین شده و به ترتیب آرایه بستگی ندارد.
- **دسکتاپ (بیشتر از ۶۴۰px):** بدون هیچ انیمیشنی؛ هر چهار کارت از ابتدا باز هستند (قانون `@media (min-width: 641px)` روی `.rsn-slot`) و کد اسکرول اصلاً اجرا نمی‌شود. با hover آیکون کمی می‌چرخد، خط طلایی بلندتر و عکس کمی بزرگ‌تر می‌شود.
- **موبایل (۶۴۰px و کمتر):** هر کارت تا باز نشده **هیچ جایی نمی‌گیرد** (`grid-template-rows: 0fr`)، بنابراین زیر بخش فضای سفید خالی نمی‌ماند و بخش با باز شدن هر کارت بزرگ می‌شود (مثل کرکره). کارت‌ها یکی‌یکی و با فاصله‌ی `260` میلی‌ثانیه (عددی در `step`) باز می‌شوند و زمان باز شدن هر کدام ۰٫۴ ثانیه است (`transition` روی `.rsn-slot` در بخش موبایل CSS).
  - **رسیدن از بالا** (اسکرول به پایین): از اولین کارت به آخرین؛ بخش رو به **پایین** رشد می‌کند.
  - **رسیدن از پایین** (اسکرول به بالا): از آخرین کارت به اولین؛ کارت‌ها از لبه‌ی پایین خودشان باز می‌شوند (کلاس `rise`) و بخش رو به **بالا** رشد می‌کند. برای این‌که آنچه زیر بخش است سر جایش بماند، یک `ResizeObserver` در همان فریم صفحه را به اندازه‌ی رشد اسکرول می‌کند. فاصله‌ی کسری پیکسل‌ها نگه داشته می‌شود تا کم‌کم جابه‌جا نشود.
  - **بسته شدن:** وقتی کل بخش از صفحه بیرون رفت (کنترل روی `scroll` در تابع `sweep`)، همه‌ی کارت‌ها بسته می‌شوند تا دفعه‌ی بعد دوباره پخش شوند. اگر بخش بالای صفحه باشد، کارت‌ها بلافاصله و بدون انیمیشن بسته می‌شوند و صفحه به اندازه‌ی ارتفاع از دست‌رفته اسکرول می‌شود تا هیچ‌چیز جابه‌جا نشود.
  - جهت و شروع را `IntersectionObserver` با باند ۸٪ تا ۹۲٪ ارتفاع صفحه تشخیص می‌دهد؛ چیزی که زیر نظر است `.rsn-slot` است، نه خود کارت (کارتی که با انیمیشن بریده می‌شود برای مرورگر «نامرئی» حساب می‌شود و حلقه‌ی باز و بسته شدن ایجاد می‌کند).
  - تا وقتی این بخش روی صفحه است `overflow-anchor: none` روی `<html>` گذاشته می‌شود، چون جای صفحه را خود کد نگه می‌دارد.
- **کاهش حرکت:** اگر کاربر «کاهش حرکت» را روشن کرده باشد، `transition` برداشته می‌شود و کارت‌ها بدون حرکت باز می‌شوند.

### بخش سه‌مرحله‌ای (`Journey.jsx`)

این بخش با **GSAP ScrollTrigger** کار می‌کند و چهار حالت دارد که خودکار انتخاب می‌شوند:

| حالت | چه زمانی | رفتار |
|---|---|---|
| `PinnedJourney` | دسکتاپ (بیشتر از ۹۸۰px) | بخش زیر هدر ثابت می‌ماند؛ با اسکرول، متن، تصویر داخل گوشی و نشانگر خط وسط هم‌زمان عوض می‌شوند؛ گوشی در هر مرحله به طرف دیگر می‌رود |
| `MobilePinnedJourney` | موبایل و تبلت | بخش ثابت می‌ماند؛ قاب گوشی ثابت است و صفحه‌ی داخلش اسکرول می‌شود (نوار وضعیت و منوی پایین ثابت)، متن بالا و خط کنار گوشی هم‌زمان حرکت می‌کنند |
| `StaticJourney` | دسکتاپ با «کاهش حرکت» | سه ردیف ثابت، یک‌درمیان |
| `MobileJourney` | موبایل با «کاهش حرکت» | سه بخش عادی زیر هم، بدون ثابت ماندن |

«کاهش حرکت» همان تنظیم سیستم‌عامل است (در ویندوز: *Settings → Accessibility → Visual effects → Animation effects*). اگر خاموش باشد، بخش عمداً بدون انیمیشن نمایش داده می‌شود.

نکته‌های فنی:

- **تصاویر:** قاب گوشی یک PNG شفاف است و سه اسکرین‌شات زیر آن قرار می‌گیرند. موقعیت صفحه‌ی گوشی با درصدهایی که از روی خود تصویر اندازه گرفته شده تنظیم شده (کامنت‌های بالای `.jr-device` در CSS). اگر قاب را با تصویر دیگری عوض کنید، این درصدها باید دوباره اندازه‌گیری شوند.
- **طول اسکرول:** هر حالت ثابت به اندازه‌ی دو برابر ارتفاع صفحه طول می‌کشد (`end: … window.innerHeight * 2` در `Journey.jsx`).
- **ارتفاع هدر:** ثابت‌ها زیر هدر قرار می‌گیرند؛ عدد آن در `HEADER_H = 73` تعریف شده. اگر ارتفاع هدر عوض شد، این عدد و `73px`های CSS همین بخش را هم عوض کنید.
- **پاک‌سازی:** GSAP از `useLayoutEffect` و `gsap.context` استفاده می‌کند و هنگام عوض شدن حالت (مثلاً کوچک کردن پنجره) همه‌چیز را پاک می‌کند. دور بخش ثابت یک `div.jr-pin-wrap` هست که نباید حذف شود؛ بدون آن React هنگام عوض شدن حالت خطا می‌دهد.

### کاروسل مقالات

با انگشت یا تاچ‌پد به‌صورت عادی اسکرول می‌شود و با ماوس هم قابل کشیدن است (`useDragScroll`).

### اضافه کردن بخش جدید

1. فایل `src/components/NewSection.jsx` بسازید که یک `<section className="container …">` برمی‌گرداند.
2. آن را در `App.jsx` ایمپورت کنید و در جای دلخواه داخل `<main>` بگذارید.
3. استایلش را با یک کامنت عنوان به انتهای `styles.css` اضافه کنید.
4. اگر انیمیشن ظاهر شدن می‌خواهد، کلاسش را به `revealSel` اضافه کنید.

## پیش از انتشار

این موارد در کد یا تصاویر فعلی هست و باید پیش از انتشار عمومی بررسی شوند:

- **عکس‌های journey:** روی اسکرین‌شات‌های `journey/` نام برند **ArianaPay** (و «ایرناپی») نوشته شده، نه AryanaPay.
- **لینک‌ها:** بسیاری از دکمه‌ها و لینک‌ها (فروشگاه‌های اپ، کارت‌های امکانات، شبکه‌های اجتماعی، فوتر) هنوز به `#` اشاره می‌کنند.
- **متن و عکس نمونه:** متن و عکس‌های کارت‌های امکانات (`Features.jsx`) و مبلغ‌ها و هدف‌های بخش هدف‌های مالی (`Goals.jsx`) نمونه‌اند و باید با محتوای واقعی عوض شوند.
- **هیرو:**
  - کارت بانکی داخل هیرو (نام AryanaPay، شماره‌ی `1234 5678 9012 3456`، تاریخ `12/28`) و مبالغ کارت‌های کناری **نمایشی** هستند.
  - عکس هیرو فقط ۱۷۵۶px عرض دارد و روی نمایشگرهای بزرگ‌تر از حدود ۱۹۲۰px کمی نرم دیده می‌شود.
  - پوشه‌ی `dist/` با هر `npm run build` پاک می‌شود؛ عکس‌های کار را فقط داخل `src/assets` نگه دارید.
- **حجم تصاویر:** چهار تصویر بخش سه‌مرحله‌ای PNG هستند (حدود ۱.۱ مگابایت با هم)؛ تبدیل به WebP صفحه را سبک‌تر می‌کند.
- **کد QR** در بخش اپلیکیشن فعلاً یک الگوی نمایشی است، نه QR واقعی.
