این پوشه (`aryana-react`) خود سایت است. (نسخه‌ی قدیمی HTML/CSS/JS ساده‌ی سایت از ریپو حذف شده؛ در تاریخچه‌ی گیت، قبل از کامیت `022ab4a`، هنوز هست.)

## اجرای پروژه

**پیش‌نیاز:** Node.js نسخه‌ی ۲۰ یا بالاتر (پروژه با Node 24 تست شده است).

بار اول، داخل همین پوشه کتابخانه‌ها را نصب کنید:

```
npm install
```

### اجرا هنگام توسعه

یکی از این سه راه:

| راه | کار |
|---|---|
| دوبار کلیک روی `start.bat` | اگر لازم باشد نصب می‌کند، سرور را بالا می‌آورد و مرورگر را باز می‌کند |
| `npm run dev` در همین پوشه | سرور توسعه روی http://localhost:5173 |
| `npm run dev` در پوشه‌ی بالایی (`C:\project\aryana`) | همان، از ریشه‌ی پروژه (با `package.json` ریشه) |

با هر ذخیره‌ی فایل، صفحه خودش به‌روز می‌شود.

> فایل `index.html` را با دوبار کلیک (آدرس `file://`) باز نکنید؛ صفحه سفید می‌ماند. پروژه‌ی Vite فقط از طریق سرور اجرا می‌شود.

### دستورها

| دستور | کار |
|---|---|
| `npm run dev` | سرور توسعه |
| `npm run build` | ساخت خروجی نهایی در پوشه‌ی `dist` |
| `npm run preview` | اجرای همان خروجی نهایی روی http://localhost:4173 برای تست |
| `npm run lint` | بررسی کد با oxlint |

## ساختار پوشه‌ها

```
aryana-react/
├─ index.html              پوسته‌ی صفحه: عنوان، فونت‌ها، آیکون‌های SVG و <div id="root">

├─ vite.config.js          تنظیمات Vite

├─ backup/                 نسخه‌های پشتیبان هیروهای قبلی (در سایت استفاده نمی‌شوند؛ هر پوشه README دارد)
├─ dist/                   خروجی build؛ با هر build **پاک و دوباره ساخته می‌شود** (چیزی را فقط این‌جا نگه ندارید)
└─ src/
   ├─ main.jsx             نقطه‌ی شروع؛ React و styles.css را لود می‌کند
   ├─ App.jsx              ترتیب بخش‌های صفحه
   ├─ styles.css           همه‌ی استایل‌ها
   ├─ components/          هر بخش صفحه یک فایل
   ├─ hooks/               رفتارهای قابل استفاده‌ی مجدد (اسکرول، درگ، …)
   ├─ data/content.js      متن‌ها و لیست‌ها

```

## محتوا و متن‌ها

بیشتر متن‌ها در [`src/data/content.js`](src/data/content.js) هستند، به شکل لیست. کامپوننت روی لیست حلقه می‌زند، پس برای افزودن یک مورد فقط یک خط اضافه کنید:

```js
export const faqs = [
  { q: 'سوال؟', a: 'جواب.' },
  // مورد جدید را این‌جا اضافه کنید
]
```

- بین آیتم‌ها ویرگول لازم است.
- متن بین دو `'` می‌آید؛ اگر خود متن `'` داشت، دورش را با `"` ببندید.
- عنوان هر آیتم (`title`، `q`، `label`) باید در لیست خودش یکتا باشد، چون React از آن به‌عنوان کلید استفاده می‌کند.

### تصاویر

تصاویر در `src/assets/photos/` هستند و بالای کامپوننت `import` می‌شوند؛ Vite هنگام build آن‌ها را بهینه و نام‌گذاری می‌کند. برای عوض کردن یک تصویر، فایل جدید را در همین پوشه بگذارید و خط `import` را عوض کنید (یا فایل را با همان نام جایگزین کنید).

| تصویر | کجا |
|---|---|
| `hero/tehran-hero.webp` | پس‌زمینه‌ی آبی هیرو (افق تهران، برج میلاد و موج نورانی) و عکس داخل کارت وسط |
| `hero/tehran-alborz.webp` و `hero/tehran-alborz-line.webp` | بخش هدف‌های مالی: افق رنگی و همان افق به‌صورت طرح خطی بی‌رنگ (هر دو روی زمینه‌ی سفید و مات‌اند) |
| `journey/` (قاب گوشی + سه اسکرین‌شات اپ، WebP) | بخش سه مرحله‌ای (Journey)، گوشی در AppBanner، سه گوشی هیرو و گوشی‌های صفحه‌ی «درباره ما». **اسکرین‌شات‌ها** را ببینید |
| `feature-cards.webp` و `feature-wallet.webp` | تکه‌هایی از صفحه‌ی «مدیریت کارت‌ها» و «کیف پول» اپ، داخل دو کارت پهن در `Features.jsx` (برش‌خورده به شکل جعبه‌ی عکس، حدود ۷ به ۴) |
| `card-front.png` (کارت آریانا بریده‌شده از موکاپ، پس‌زمینه شفاف) | کارت ریالی در صفحه‌ی «درباره ما» (هیرو، «داستان ما» و کارت‌های محصول) |
| `ft-cbi.png`، `ft-enamad.png` | فوتر و نشان «مجوز بانک مرکزی» زیر کارت‌ها |
| `logo/` | لوگو و نماد (نسخه‌ی روشن برای زمینه‌ی تیره) |

عکس‌های امکانات (`Features.jsx`) تکه‌های اسکرین‌شات اپ‌اند؛ برای عوض کردن، فایل جدید را در همین پوشه بگذارید و `import` بالای فایل و فیلد `img` همان کارت را عوض کنید. برای کارت بدون عکس فقط `img` را ننویسید.

**اسکرین‌شات‌های اپ (`journey/aryanapay-*.webp`):** سه صفحه‌ی اپ، هر کدام به اندازه‌ی ۶۴۰ × ۱۲۲۶ و با نسبت صفحه‌ی قاب گوشی (۵۷۹ به ۱۱۰۹)، تا بدون برش و کشیدگی در قاب بنشینند. اسکرین‌شات‌های اپ پهن‌ترند؛ پس برای ساختن این فایل‌ها بالا زیر ناچ (۴٫۶٪ ارتفاع) هم‌رنگ پس‌زمینه‌ی اپ خالی می‌ماند و بقیه‌ی ارتفاع با تکرار یک ردیف یکدست (فاصله‌ی بین دو بلوک) بین چند جای خالی پخش می‌شود، نه با کشیدن تصویر. نام فایل‌ها و جایشان: `aryanapay-payments.webp` = «مدیریت کارت‌ها» (مرحله‌ی اول Journey، گوشی وسط هیرو، گوشی AppBanner و «درباره ما»)، `aryanapay-transfer.webp` = «شارژ سریع»، `aryanapay-dashboard.webp` = «کیف پول». برای عوض کردن یک صفحه، تصویر جدید را با همین نسبت و نام جایگزین کنید.

## استایل، رنگ‌ها و آیکون‌ها

همه‌ی استایل‌ها در [`src/styles.css`](src/styles.css) هستند. هر بخش با یک کامنت شروع می‌شود (مثلاً `/* Contact form */`)؛ برای پیدا کردن استایل یک بخش، اسم آن را با Ctrl+F جستجو کنید. استایل‌های بخش‌هایی که بعداً اضافه شده‌اند در انتهای فایل هستند.

### رنگ‌ها و مقادیر پایه

بالای `styles.css` در `:root` تعریف شده‌اند و همه‌جا با `var(...)` استفاده می‌شوند:

| متغیر | مقدار | کاربرد |
|---|---|---|
| `--navy` | `#1a3b66` | رنگ اصلی برند |
| `--navy-2` | `#12294a` | تیترها |
| `--blue` | `#2962a8` | لینک‌ها و حالت فعال |
| `--yellow` | `#e19c26` | طلایی برند، دکمه‌ی اصلی |
| `--muted` | `#5b6b82` | متن‌های توضیحی |
| `--bg` | `#f8f9fa` | پس‌زمینه‌ی کادرها |
| `--line` | `#d0d7dd` | خطوط و حاشیه‌ها |
| `--radius` | `16px` | گردی گوشه‌ی کادرها |

فونت‌ها (Vazirmatn برای فارسی، Poppins برای اعداد و لاتین) از Google Fonts در `index.html` لود می‌شوند.

### عرض صفحه و نقاط شکست

- عرض محتوا: `.container` با حداکثر **۱۲۴۰ پیکسل** و ۴۰ پیکسل فاصله از هر طرف (در موبایل ۲۴ پیکسل و در ۳۸۰px و کمتر ۲۰ پیکسل).
- نقاط شکست اصلی: `980px` (تبلت؛ بیشتر چیدمان‌ها یک‌ستونه می‌شوند)، `760px` (موبایل) و `380px` (موبایل کوچک).

### آیکون‌ها

همه‌ی آیکون‌ها در یک «اسپرایت» SVG در ابتدای `<body>` فایل `index.html` هستند، هر کدام یک `<symbol id="i-…">`. در کد با کامپوننت `Icon` استفاده می‌شوند:

```jsx
<Icon name="download" className="ic" />   // از symbol با id="i-download"
```

برای آیکون جدید، یک `<symbol id="i-اسم">` به `index.html` اضافه کنید.

### موبایل: حاشیه و متن‌ها

همه‌ی این‌ها فقط در موبایل (۷۶۰px و کمتر) اعمال می‌شوند و در انتهای `styles.css` هستند:

- **حاشیه‌ی دو طرف:** همه‌ی بخش‌ها از `.container` استفاده می‌کنند و ۲۴px از هر طرف حاشیه دارند. بخش ثابتِ Journey هم همین عدد را دارد تا تیترها هم‌راستا باشند.
- **راستای تیترها:** تیتر و پاراگراف زیرش هر دو از لبه‌ی راست شروع می‌شوند (`text-align: start`)، نه وسط‌چین.
- **پاراگراف‌ها جاستیفای** هستند (`text-align: justify`، `text-align-last: start`، `text-wrap: pretty` تا یک کلمه‌ی تنها در خط آخر نماند). فهرست انتخابگرها یک‌جا در همان بلوک است. متن کارت‌های امکانات استثناست (ستون باریک است).
- **بنر اپلیکیشن:** تیتر «همه چیز در یک اپلیکیشن» بزرگ می‌شود تا درست به اندازه‌ی عرض متن زیرش باشد (`--t` و `container-type` روی `.app-banner`؛ `9.93` عرض خط تیتر بر حسب فونت است. اگر متن تیتر عوض شد، این عدد را دوباره حساب کنید). سه دکمه‌ی دانلود در یک ردیف و هم‌اندازه‌اند و آیکون بالای متن است (تا ۵۶۰px). گوشی سایه ندارد و ۱۴px به چپ و پایین رفته است.
- **هیرو:** گوشه‌ی کارت ایستاده و کارتِ افتاده ۱۴px است (`.rv-hero-card-in` و `.rv-hero-fall`).
- **هدر و فوتر:** دکمه‌ی تغییر زبان وجود ندارد (در هدر و فوتر حذف شده)، و دور لوگو کادر فوکوس نیست.

## انیمیشن‌ها و اسکرول

### ظاهر شدن بخش‌ها (`useReveal`)

بخش‌هایی که در لیست `revealSel` در [`src/hooks/useReveal.js`](src/hooks/useReveal.js) هستند، هنگام رسیدن به صفحه نرم ظاهر می‌شوند. شکل حرکت در CSS است (کلاس‌های `.reveal` و `.reveal.in`). برای این‌که بخشی انیمیشن بگیرد، کلاسش را به `revealSel` اضافه کنید.

### هیرو (`Hero.jsx`)

هیرو یک صفحه‌ی کامل است که با اسکرول به صفحه‌ی دوم (سفید با سه کارت) تبدیل می‌شود. متن‌ها داخل خود کامپوننت‌اند و عکس‌ها از `PHOTOS` بالای فایل خوانده می‌شوند. بر پایه‌ی **GSAP ScrollTrigger** است و دو حالت دارد که با عرض صفحه (۷۶۰ پیکسل) خودکار انتخاب می‌شوند.

**دسکتاپ (بیشتر از ۷۶۰px، با انیمیشن)**

- هیرو یک صفحه‌ی کامل (`100svh`) است و ۷۳ پیکسل بالایش **زیر هدر** می‌رود (`.rv-wrap { margin-top: -73px }`). هدر روی آن شفاف است، پس عکس تا بالاترین لبه ادامه دارد.
- ScrollTrigger هیرو را به اندازه‌ی ۳ برابر ارتفاع صفحه ثابت نگه می‌دارد (`end` در `Hero.jsx`). `scrub: 0.8` حرکت را به اسکرول وصل می‌کند و `snap` (با `directional: true`) بعد از یک اسکرول کوتاه، انیمیشن را خودکار تا آخر (یا تا اول) می‌برد.
- مراحل تایم‌لاین: **کارت افقی می‌چرخد و عمودی می‌شود** ← متن هیرو بالا می‌رود و محو می‌شود ← عکس آبی با `clip-path` به قاب کارت بزرگ کوچک می‌شود (گوشه‌ها از همان ابتدا با شعاع ثابت ۲۲px) ← عکس و کارت با هم بالا می‌آیند و در گوشی وسط می‌نشینند ← کارت بانکی به صفحه‌ی اپ تبدیل می‌شود ← عنوان، دکمه و دو گوشی کناری وارد می‌شوند.
- **کارت افقی در شروع:** صفحه با یک کارت **افقی** شروع می‌شود (`BankCard land`، کلاس `.rv-land` داخل `.rv-frame`؛ همان طراحی کارت، با چیدمان افقی و اندازه‌هایی که با `cqw` از عرض خودش حساب می‌شوند). طول آن به اندازه‌ی ارتفاع کارت عمودی است و در وسط آن می‌نشیند. در شروع تایم‌لاین (`TURN = 1.1` ثانیه) یک چهارم دور می‌چرخد و هم‌زمان از `y: 90` به جای اصلی بالا می‌آید، سپس در همان جا با کارت عمودی جایگزین می‌شود (`autoAlpha` هر دو و `--frame-on` برای حاشیه‌ی قاب). **انیمیشن قبلی بدون تغییر ادامه پیدا می‌کند:** این چرخش با `tl.shiftChildren(TURN)` همه‌ی تایم‌لاین قبلی را به اندازه‌ی ۱٫۱ ثانیه عقب می‌برد، و طول اسکرول (`end`) به نسبت بیشتر شده (از ۳ به ۳٫۸ برابر ارتفاع صفحه) تا سرعت انیمیشن قبلی همان بماند. اگر `TURN` را عوض کردید، `end` را هم به همان نسبت عوض کنید. برای جابه‌جایی کارت افقی بالا و پایین، عدد `y` در همان `fromTo` را عوض کنید (بزرگ‌تر یعنی پایین‌تر).
- **سه کارت صفحه‌ی دوم گوشی‌اند** (`PhoneBody`: صفحه‌ی اپ داخل تصویر قاب گوشی، با همان درصدهای `.jr-device`): وسط «مدیریت کارت‌ها»، دو طرف «کیف پول» و «شارژ سریع». جعبه‌ی هر کارت اندازه‌ی بدنه‌ی گوشی است (`aspect-ratio: 660 / 1183`)، پس کل صفحه‌ی اپ بدون برش دیده می‌شود. عرض گوشی وسط `--cw` است (`min(340px, 24vw, …)`) و فاصله‌ی گوشی‌ها در `.rv-cards` ۵۶px (`gap`). گوشی‌ها سایه ندارند.
- **کارت بانکی به گوشی تبدیل می‌شود:** گوشی وسط (`.rv-app-slot`) بعد از نشستن کارت بانکی ظاهر می‌شود، در حالی که کارت بانکی (`.rv-frame`) و لایه‌ی عکس (`.rv-clip`) محو می‌شوند. عکس محو می‌شود چون بدنه‌ی گرد گوشی گوشه‌های مستطیل عکس را نشان می‌داد.
- **اندازه‌گیری دوباره:** انیمیشن جای کارت وسط را یک بار می‌سنجد؛ پس بعد از آماده شدن فونت‌ها و هرگاه ارتفاع بخش متن بالای کارت‌ها عوض شود (`ResizeObserver` روی `.rv-next-head`) `ScrollTrigger.refresh()` صدا زده می‌شود. بدون این، با عوض شدن تعداد خط‌های متن، عکس و کارت از هم جدا می‌ماندند.
- `clip-path` با سه مقدار پیشرفت (`a`، `b`، `rad`) و تابع `paint()` مقدار می‌گیرد، نه با انیمیت مستقیم رشته‌ی `clip-path`؛ تا شعاع گوشه مستقل از حرکت لبه‌ها بالا برود.
- **جای کارت بزرگ** در تابع `heroRect` محاسبه می‌شود: اندازه `۰٫۶۴ × ارتفاع قابل‌استفاده` (حداکثر ۲۸٪ عرض صفحه)، کمی چپ‌تر از وسط (`cx` تا ۴۶٪ عرض، با ۴۰px فاصله از عنوان) و کمی پایین‌تر از مرکز عمودی (`+ ۶٪` ارتفاع). برای جابه‌جایی یا تغییر اندازه فقط همین ضرایب را عوض کنید.
- **هدر و هیرو:** تا وقتی هیرو ثابت است، هدر شفاف می‌ماند (صفت `data-hero-pinned` روی `<html>`) و رنگ متنش سفید است تا عکس زیرش لبه‌ی بالایش را می‌پوشاند (`data-hero-covers`)؛ بعد با fade کوتاه تیره می‌شود. بعد از پایان هیرو، هدر سفیدِ blurدار عادی می‌شود. منطق سمت هدر در `Header.jsx` و رنگ‌ها در `.site-header.on-hero` و `html[data-hero-pinned] .site-header` (CSS) است.
- **کارت بانکی** (`BankCard`): کارت سرمه‌ای عمودی با CSS ساخته شده (لوگو، تراشه، شماره، تاریخ)، نه عکس. همه‌ی اندازه‌هایش با `cqw` (درصد عرض قاب) است و کل قاب را می‌پوشاند.
- **نور جاری روی موج** (`WaveGlow`): دو مسیر SVG (`WAVE` طلایی و `WAVE_B` سفید-آبی) روی موج‌های خود عکس کشیده شده‌اند و چند پرتو نور (`stroke-dasharray` انیمیت‌شده) در طولشان حرکت می‌کند. SVG با `preserveAspectRatio="xMinYMid slice"` هم‌اندازه با عکس (`object-fit: cover` و `object-position: 0% 50%`) می‌ماند. **اگر عکس هیرو را عوض کنید، این دو مسیر باید دوباره روی موج عکس جدید کشیده شوند.**

**موبایل (۷۶۰px و کمتر)**

- انیمیشن اسکرولی و ثابت ماندن وجود ندارد؛ کلاس `rv-static` (همان حالت «کاهش حرکت») اعمال می‌شود: صفحه‌ی اول عکس + متن + کارت بزرگ ثابت، و زیرش بخش دوم.
- **هدر:** چون عکس زیر هدر نمی‌رود، بالای صفحه هدر آبی یکدست است (`#2369c5`، گوشه‌ی بالا-چپ عکس هیرو؛ در `.site-header.on-hero`) و با اسکرول سفید می‌شود.
- **کارت بزرگ** (`.rv-hero-card`) تقریباً تمام‌عرض است (۱۲px فاصله از هر طرف) و زیر دکمه قرار می‌گیرد؛ پایین متن در جاوااسکریپت اندازه‌گیری و به CSS داده می‌شود (`--copy-b`).
- **سه کارت** (گوشی‌ها) به‌صورت **حلقه**: کارت وسط بزرگ، دو کارت کناری کوچک و کم‌رنگ با نواری باریک از آن‌ها در لبه‌ی صفحه. هر ۳٫۲ ثانیه (`setInterval` در `Hero.jsx`) هر کارت به جای بعدی می‌رود. با کشیدن انگشت هم می‌چرخد. جابه‌جایی فقط با `transform` است (`startLive` / `step` / `stopLive`).
- **چیدمان سه‌تایی در همه‌ی لحظه‌ها:** چرخش یک حرکت یکپارچه است، نه حرکت جدای هر کارت: یک عدد پیشرفت (`prog.t`، از ۰ تا ۱، در ۰٫۴۵ ثانیه، `power2.inOut`) هر سه کارت را با هم جابه‌جا می‌کند و شکل هر کارت (اندازه، رنگ‌پریدگی، `zIndex`) را تابع `placeAt(i, u)` از فاصله‌ی آن تا وسط حساب می‌کند. هرچه کارت به وسط نزدیک‌تر باشد بزرگ‌تر، پررنگ‌تر و بالاتر است. کارتی که باید از یک سر به سر دیگر برود از پشت بقیه رد **نمی‌شود**: از لبه‌ی خودش بیرون می‌رود و یک **کپی** از آن (`copies` در `step`) هم‌زمان از لبه‌ی مقابل وارد می‌شود؛ در پایان چرخش کپی برداشته می‌شود و کارت واقعی جای آن می‌نشیند. بدین‌ترتیب در هر لحظه یک کارت در هر لبه و یکی وسط است. برای تندتر یا کندتر کردن، `duration` در `step` را عوض کنید.

**کاهش حرکت:** هیرو با چیدمان ثابت `rv-static` (صفحه‌ی اول، زیرش صفحه‌ی دوم)، بدون ثابت ماندن، بدون چرخش کارت‌ها و با نور موجِ خاموش نمایش داده می‌شود.

**نکته‌های فنی**

- `HEADER_H = 73` در `Hero.jsx` ارتفاع هدر است؛ اگر ارتفاع هدر عوض شد، این عدد و `73px`های بخش `.rv` در CSS را عوض کنید.
- دور بخش ثابت یک `div.rv-wrap` هست که نباید حذف شود (GSAP `pin-spacer` را داخل آن می‌گذارد).
- پاک‌سازی (ScrollTrigger، شنونده‌ها، صفت‌های `data-hero-*`) در `useLayoutEffect` انجام می‌شود و با عوض شدن حالت (کوچک/بزرگ شدن پنجره) دوباره ساخته می‌شود.
- پیش از این، هیروی قبلی و هیروی متحرک دوم در `backup/` نگه داشته شده‌اند.

### هدف‌های مالی (`Goals.jsx`)

عکس تمام‌عرض افق تهران با تیتر «یک کارت برای همه‌ی اپلیکیشن‌هایتان»، توضیح (خرید از فروشگاه‌ها، پرداخت هزینه‌ی اپلیکیشن‌ها و ابزارهای هوش مصنوعی و شارژ حساب‌ها)، یک نکته‌ی کوتاه، دکمه و کارت بانکی شناور. عکس از یک **طرح خطی بی‌رنگ** شروع می‌شود و رنگ می‌گیرد؛ متن‌ها و کارت یکی‌یکی وارد می‌شوند. همه‌ی ترتیب‌ها در یک تایم‌لاین GSAP هستند.

- **دسکتاپ:** بخش با ScrollTrigger ثابت می‌ماند (`pin`) و تایم‌لاین با اسکرول جلو می‌رود (`scrub`)، به طول `window.innerHeight * 2.4`.
- **موبایل (۷۶۰px و کمتر):** اسکرول ثابتی ندارد. وقتی بخش به ۸۸٪ پایین صفحه برسد، همان تایم‌لاین **خودش و بر پایه‌ی زمان** پخش می‌شود و هر بار که دوباره به بخش برسید از اول پخش می‌شود. زمان‌بندی هر عنصر در شیء `t` داخل `Goals.jsx` است (یک ستون برای موبایل، یک ستون برای دسکتاپ): تیتر و جمله‌ی بعدش تقریباً بلافاصله می‌آیند، بعد نکته، دکمه و در آخر کارت.
- **رنگی شدن:** دو عکس (رنگی و خطی) هر دو **مات** و با زمینه‌ی سفیدند. عکس رنگی زیر و با قدرت کامل می‌ماند و فقط طرح خطی روی آن محو می‌شود؛ اگر هر دو هم‌زمان محو شوند، وسط کار زمینه‌ی سفید دیده می‌شود و تصویر رنگ‌پریده می‌شود. روی این دو عکس هیچ `transition` در CSS نگذارید، با انیمیشن GSAP درگیر می‌شود.
- **موبایل، راستا:** تیتر، جمله‌ها و دکمه همه از لبه‌ی راست ستون شروع می‌شوند (`.gl-body { align-items: stretch }` و `.gl-cta { align-self: flex-start }`) و فقط کارت بانکی وسط می‌ماند (`.gl-bank-wrap { align-self: center }`)؛ بخش «موبایل: حاشیه و متن‌ها» را ببینید.
- **موبایل، چیدمان:** متن‌ها با `top: -50px` (در موبایل‌های کوتاه‌تر از ۶۴۰px فقط `-30px`) کمی بالاتر از جای عادی‌اند (فقط جابه‌جایی ظاهری؛ کارت و بقیه جابه‌جا نمی‌شوند)، رنگ تیتر کمی روشن‌تر است و کارت ۲۸px پایین‌تر. همه در انتهای بخش `.gl` در `styles.css`.
- نام‌های `GOALS` و عکس‌ها از زمانی که این بخش درباره‌ی هدف مالی بود مانده‌اند (فعلاً فقط عکس تهران استفاده می‌شود).

### کارت‌های امکانات (`Features.jsx`)

چهار کارت روشن در دو ردیف: ردیف اول یک کارت پهن و یک کارت باریک، ردیف دوم برعکس. هر کارت یک آیکون در مربع سرمه‌ای، عنوان و یک جمله دارد؛ دو کارت پهن («مدیریت از اپلیکیشن» و «کیف پول») تکه‌ای از اسکرین‌شات اپ دارند که در رنگ کارت محو می‌شود. «انتقال و شارژ سریع» و «امنیت و اطمینان» ساده‌اند. متن‌ها، آیکون‌ها و عکس‌ها در آرایه‌ی `CARDS` بالای فایل‌اند، نه در `content.js`.

- **ترتیب آرایه** همان ترتیب کارت‌ها در موبایل است و طوری چیده شده که کارت‌های عکس‌دار و بی‌عکس یک‌درمیان باشند (`a`، `b`، `d`، `c`). جای کارت‌ها در دسکتاپ جدا و با `grid-column` و `grid-row` روی `.rsn-slot.a` تا `.d` تعیین شده و به ترتیب آرایه بستگی ندارد.
- **دسکتاپ (بیشتر از ۶۴۰px):** بدون هیچ انیمیشنی؛ هر چهار کارت از ابتدا باز هستند (قانون `@media (min-width: 641px)` روی `.rsn-slot`) و کد اسکرول اصلاً اجرا نمی‌شود. با hover آیکون کمی می‌چرخد و عکس کمی بزرگ‌تر می‌شود.
- **موبایل (۶۴۰px و کمتر):** هر کارت تا باز نشده **هیچ جایی نمی‌گیرد** (`grid-template-rows: 0fr`)، بنابراین زیر بخش فضای سفید خالی نمی‌ماند و بخش با باز شدن هر کارت بزرگ می‌شود (مثل کرکره). کارت‌ها یکی‌یکی و با فاصله‌ی `320` میلی‌ثانیه (عددی در `step`) باز می‌شوند و زمان باز شدن هر کدام ۰٫۵ ثانیه است (`transition` روی `.rsn-slot` در بخش موبایل CSS).
  - **رسیدن از بالا** (اسکرول به پایین): از اولین کارت به آخرین؛ بخش رو به **پایین** رشد می‌کند.
  - **رسیدن از پایین** (اسکرول به بالا): از آخرین کارت به اولین؛ کارت‌ها از لبه‌ی پایین خودشان باز می‌شوند (کلاس `rise`) و بخش رو به **بالا** رشد می‌کند. برای این‌که آنچه زیر بخش است سر جایش بماند، یک `ResizeObserver` در همان فریم صفحه را به اندازه‌ی رشد اسکرول می‌کند. فاصله‌ی کسری پیکسل‌ها نگه داشته می‌شود تا کم‌کم جابه‌جا نشود.
  - **بسته شدن:** وقتی کل بخش از صفحه بیرون رفت (کنترل روی `scroll` در تابع `sweep`)، همه‌ی کارت‌ها بسته می‌شوند تا دفعه‌ی بعد دوباره پخش شوند. اگر بخش بالای صفحه باشد، کارت‌ها بلافاصله و بدون انیمیشن بسته می‌شوند و صفحه به اندازه‌ی ارتفاع از دست‌رفته اسکرول می‌شود تا هیچ‌چیز جابه‌جا نشود.
  - جهت و شروع را `IntersectionObserver` با باند ۸٪ تا ۹۲٪ ارتفاع صفحه تشخیص می‌دهد؛ چیزی که زیر نظر است `.rsn-slot` است، نه خود کارت (کارتی که با انیمیشن بریده می‌شود برای مرورگر «نامرئی» حساب می‌شود و حلقه‌ی باز و بسته شدن ایجاد می‌کند).
  - تا وقتی این بخش روی صفحه است `overflow-anchor: none` روی `<html>` گذاشته می‌شود، چون جای صفحه را خود کد نگه می‌دارد.
- **موبایل، متن کارت‌ها:** ستون متن همه‌ی کارت‌ها از یک لبه شروع می‌شود. کارت‌های عکس‌دار (`b`، `c`) حداکثر `168px` عرض متن دارند تا روی عکس نروند و کارت‌های ساده (`a`، `d`) `232px`؛ این دو یک گرادیان آبی بسیار کم‌رنگ در سمت چپ دارند (`.rsn-card.a`، `.rsn-card.d` در بخش موبایل CSS) تا آن سمت خالی نماند.
- **کاهش حرکت:** اگر کاربر «کاهش حرکت» را روشن کرده باشد، `transition` برداشته می‌شود و کارت‌ها بدون حرکت باز می‌شوند.

### بخش سه‌مرحله‌ای (`Journey.jsx`)

این بخش با **GSAP ScrollTrigger** کار می‌کند و چهار حالت دارد که خودکار انتخاب می‌شوند:

| حالت | چه زمانی | رفتار |
|---|---|---|
| `PinnedJourney` | دسکتاپ (بیشتر از ۹۸۰px) | بخش زیر هدر ثابت می‌ماند؛ با اسکرول، متن، تصویر داخل گوشی و نشانگر خط وسط هم‌زمان عوض می‌شوند؛ گوشی در هر مرحله به طرف دیگر می‌رود |
| `MobilePinnedJourney` | موبایل و تبلت | بخش ثابت می‌ماند؛ قاب گوشی ثابت است و صفحه‌ی داخلش اسکرول می‌شود (نوار وضعیت و منوی پایین ثابت)، متن بالا و خط کنار گوشی هم‌زمان حرکت می‌کنند |
| `StaticJourney` | دسکتاپ با «کاهش حرکت» | سه ردیف ثابت، یک‌درمیان |
| `MobileJourney` | موبایل با «کاهش حرکت» | سه بخش عادی زیر هم، بدون ثابت ماندن |

«کاهش حرکت» همان تنظیم سیستم‌عامل است (در ویندوز: *Settings → Accessibility → Visual effects → Animation effects*). اگر خاموش باشد، بخش عمداً بدون انیمیشن نمایش داده می‌شود.

نکته‌های فنی:

- **تصاویر:** قاب گوشی یک WebP شفاف است و سه اسکرین‌شات زیر آن قرار می‌گیرند، به ترتیب «مدیریت کارت‌ها»، «شارژ سریع»، «کیف پول» (آرایه‌ی `screens`). چون اسکرین‌شات‌ها نسبت خود صفحه‌ی گوشی را دارند، تمام صفحه را می‌پوشانند (`width: 100%`) و نوار بالا و پایین ثابت در موبایل از اولین تصویر گرفته می‌شود. موقعیت صفحه‌ی گوشی با درصدهایی که از روی خود تصویر اندازه گرفته شده تنظیم شده (کامنت‌های بالای `.jr-device` در CSS). اگر قاب را با تصویر دیگری عوض کنید، این درصدها باید دوباره اندازه‌گیری شوند.
- **متن‌ها:** شماره‌ی مرحله (۰۱، ۰۲، ۰۳) برداشته شده و فقط تیتر و جمله مانده است. تیتر دو بخش دارد (عنوان و قسمت زرد) که در دسکتاپ زیر هم‌اند (`<br />`) و در موبایل با `.jr-text h2 br { display: none }` در یک خط می‌آیند؛ فونت تیتر در موبایل ۲۴px و در ۴۳۰px و کمتر ۲۲px (و در ۳۸۰px و کمتر ۲۰px) است تا بلندترین تیتر هم در یک خط بماند.
- **موبایل، جای متن:** بلوک متن (`.jr-mtexts`) روی ته جعبه‌ی خودش می‌نشیند (`align-content: end`) و ۲۴px بالاتر برده شده (`translate`) تا فاصله‌اش با گوشی، با هر تعداد خط، ثابت و به اندازه باشد. لبه‌ی محو شدن بالا و پایین‌اش فقط ۲٪ است تا خط‌ها کم‌رنگ نشوند. فاصله‌ی دو طرف همان فاصله‌ی `.container` است (۲۴px، در ۳۸۰px و کمتر ۲۰px).
- **طول اسکرول:** هر حالت ثابت به اندازه‌ی دو برابر ارتفاع صفحه طول می‌کشد (`end: … window.innerHeight * 2` در `Journey.jsx`).
- **ارتفاع هدر:** ثابت‌ها زیر هدر قرار می‌گیرند؛ عدد آن در `HEADER_H = 73` تعریف شده. اگر ارتفاع هدر عوض شد، این عدد و `73px`های CSS همین بخش را هم عوض کنید.
- **پاک‌سازی:** GSAP از `useLayoutEffect` و `gsap.context` استفاده می‌کند و هنگام عوض شدن حالت (مثلاً کوچک کردن پنجره) همه‌چیز را پاک می‌کند. دور بخش ثابت یک `div.jr-pin-wrap` هست که نباید حذف شود؛ بدون آن React هنگام عوض شدن حالت خطا می‌دهد.

### کاروسل مقالات

با انگشت یا تاچ‌پد به‌صورت عادی اسکرول می‌شود و با ماوس هم قابل کشیدن است (`useDragScroll`).

## صفحه‌ی «درباره ما» و مسیریابی

سایت یک صفحه‌ی اصلی و یک صفحه‌ی «درباره ما» دارد. کتابخانه‌ی مسیریابی ندارد؛ صفحه با **hash** انتخاب می‌شود (هوک [`src/hooks/useRoute.js`](src/hooks/useRoute.js)، استفاده در `App.jsx`):

- `…/#/about` ← صفحه‌ی درباره ما ([`AboutPage.jsx`](src/components/AboutPage.jsx))
- هر چیز دیگر (`#faq`، `#app`، `#top` یا هیچ) ← صفحه‌ی اصلی. لینک «درباره ما» در منو و فوتر `#/about` است (در `data/content.js`).

نکته‌ها:

- با عوض شدن صفحه، بالا باز می‌شود (فوری، نه نرم؛ چون هیروی صفحه‌ی اصلی از بالای صفحه ساخته می‌شود). برگشتن به صفحه‌ی اصلی با لینک‌هایی مثل `#faq` تا آن بخش می‌رود، و باز کردن سایت مستقیم روی `…/#faq` هم همین‌طور (پس از اندازه‌گیری بخش‌های ثابت).
- هدر با `key={route}` برای هر صفحه دوباره ساخته می‌شود. در صفحه‌ی درباره ما هدر همان سفید ساده است (`route` به `Header` می‌رسد) و منو «درباره ما» را فعال نشان می‌دهد.
- هیرو هنگام خارج شدن، صفت‌های `data-hero-*` را از `<html>` برمی‌دارد (در انتهای پاک‌سازی `Hero.jsx`، پس از `ctx.revert()`)؛ وگرنه هدر در صفحه‌ی درباره ما شفاف می‌ماند.
- روی هاست، چون hash است، به تنظیم سرور (rewrite) نیازی نیست و `…/#/about` همه‌جا کار می‌کند.

**طراحی صفحه** (رنگ‌های آریانا: سرمه‌ای و زرد؛ استایل‌ها با پیشوند `.opt-` در انتهای `styles.css`). محتوای صفحه **درباره‌ی خود آریانا** و معرفی امکانات است. چهار بخش دارد:

1. **هیرو:** زمینه‌ی روشن با گرادیان بسیار ملایم؛ برچسب «درباره آریانا»، تیتر یک‌خطی «آریانا؛ خدمات مالی، **ساده و یکپارچه**» (عبارت آخر طلایی و زیرخط‌دار)، و دو جمله‌ی توضیح. زیر آن‌ها **بدون هیچ جعبه‌ای** گوشی «مدیریت کارت‌ها» وسط است (کامل و بدون برش) و دو کارت دو طرفش: کارت ریالی (`card-front.png`) راست و کارت دلاری چپ. هر کارت **در فضا به سمت گوشی برگشته** (`perspective(900px) rotateY(∓26deg)` و `rotateZ` ۳ درجه، مثل بال‌های یک سه‌تکه) و زیرش اسمش مثل متن ساده آمده. روی نمایشگر کوچک گوشی اول و دو کارت زیر آن می‌آیند.
   - **کارت دلاری هنوز تصویر ندارد:** به‌جایش **پشت یک کارت** (SVG ساده با نوار مغناطیسی و جای امضا) گذاشته‌ام (`.opt-tile-back`، با کامنت «the dollar card is not ready yet»). همین جای‌گزین در بخش «آنچه می‌سازیم» (`.opt-card-back`) هم هست. وقتی عکس کارت دلاری آماده شد، هر دو را با `<img>` عوض کنید.
2. **داستان ما** («آنچه برای شما فراهم کرده‌ایم»): سمت راست تگ، تیتر، یک جمله و فهرست شش‌تایی امکانات با تیک طلایی (آرایه‌ی `ABILITIES` بالای `AboutPage.jsx`)؛ سمت چپ دو کارت دوروی (جلو و پشت) که با اسکرول یک دور می‌چرخند. چرخش بر پایه‌ی `--s` است: فاصله‌ی علامت‌دار مرکز کارت‌ها تا وسط صفحه (۰ در یک باند میانی، ±۱ در لبه‌ها)، پس **از هر دو جهت اسکرول** (بالا و پایین) کار می‌کند. مقدار نمایش‌داده‌شده هر فریم کم‌کم به هدف می‌رسد (`0.05`)، و مسیر چرخش (`/ 1.15` در `AboutPage.jsx`) کنترل سرعت آن است (بزرگ‌تر یعنی کندتر). با «کاهش حرکت» کارت‌ها می‌ایستند.
3. **گوشی با کارت‌های دورش:** گوشی «کیف پول» (۳۲۰px) وسط و **پنج کارت، پنج تب نوار پایین اپ** (کارت‌ها، فروشگاه، شارژ سریع، کیف پول، پروفایل؛ آرایه‌ی `FEATURES`) با آیکون همان تب، اسم و یک خط معرفی: دو کارت چپ، سه کارت راست، با اندازه و فاصله‌ی متفاوت از گوشی (چیده‌شده طبق یک اسکچ؛ عددها در `.opt-feat-side-*` در CSS).
   - **انیمیشن:** با اسکرول، کارت‌ها از داخل گوشی بیرون می‌آیند و به جای خودشان می‌روند. هر کارت از مرکز گوشی (کوچک، نامرئی و پشت آن) شروع می‌کند؛ فاصله‌ی هر کارت تا گوشی (`--dx`، `--dy`) از چیدمان واقعی (`offsetLeft/Top`) اندازه گرفته می‌شود و با تغییر اندازه‌ی پنجره دوباره. هر کارت کمی دیرتر از قبلی شروع می‌کند و با منحنی نرم می‌رود؛ مقدار هر فریم کم‌کم به هدف می‌رسد (`0.07`). حرکت وقتی انجام می‌شود که بخش به جای خودش بالا می‌آید (بدون چسبیدن).
   - **مکث:** وقتی همه‌ی کارت‌ها بیرون آمدند، بخش (`.opt-feat-pin`، `position: sticky`) به‌اندازه‌ی `run` اسکرول زیر هدر **قفل** می‌ماند و بعد صفحه ادامه می‌یابد. جای قفل را `AboutPage.jsx` طوری می‌گذارد که خود گوشی و کارت‌ها کامل دیده شوند: لبه‌ی بالای آن‌ها ۱۰۰ تا ۱۵۰ پیکسل پایین‌تر از بالای صفحه (تیتر بالای بخش تا آن موقع از صفحه رفته). طول مکث `run = ارتفاع صفحه × 0.5`. روی نمایشگر کوچک (کمتر از ۹۸۰px) و با «کاهش حرکت» هیچ‌کدام از این‌ها (چسبیدن و حرکت) اجرا نمی‌شود: گوشی بالا و کارت‌ها دو‌تا‌دو زیر آن.
4. **آنچه می‌سازیم:** نوار روشن با تیتر «دو کارت و یک اپلیکیشن»، یک توضیح، دکمه‌ی دانلود و سه کارت محصول: کارت ریالی، اپلیکیشن آریانا پی (گوشی «مدیریت کارت‌ها»)، و کارت دلاری. هر کارت یک پنل تیره‌ی گرد با تصویر دارد و زیرش آیکون، اسم و یک خط توضیح.

متن‌ها در خود `AboutPage.jsx` هستند و از چیزهایی که برای کارت ریالی و دلاری و اپلیکیشن شناخته‌ایم نوشته شده‌اند (کارت ریالی برای کارت‌به‌کارت و خرید، کارت دلاری برای شارژ و انتقال دلاری، کیف پول، شارژ سریع، خرید از فروشگاه‌ها). **پیش از انتشار بررسی‌شان کنید.** عمداً رتبه‌ی ستاره‌ای، آمار، سال تجربه، تعداد کاربر، لوگوی شرکا، عکس تیم یا نظر ساختگی نگذاشته‌ام. دکمه‌ی دانلود به `#app` می‌رود.

## پیش‌نمایش لینک (Open Graph)

وقتی لینک سایت در تلگرام، واتساپ یا X فرستاده می‌شود، کارت پیش‌نمایش از تگ‌های `og:*` بالای [`index.html`](index.html) ساخته می‌شود: عنوان، توضیح، نام سایت و عکس.

- عکس پیش‌نمایش [`public/og.png`](public/og.png) است (۱۲۰۰×۶۳۰؛ لوگو و کارت آریانا روی آبی سرمه‌ای). برای عوض کردنش همین فایل را با عکس دیگری هم‌اندازه جایگزین کنید.
- `og:url` و `og:image` باید آدرس **کامل** باشند. الان `https://example.com` است؛ **بعد از انتشار** هر دو را با دامنه‌ی واقعی عوض کنید (وگرنه پیش‌نمایش نشان داده نمی‌شود).
- بعد از تغییر، کش پیام‌رسان‌ها ممکن است پیش‌نمایش قبلی را نگه دارد؛ برای تست تازه یک بار لینک را در ربات `@WebpageBot` تلگرام بفرستید.

### اضافه کردن بخش جدید

1. فایل `src/components/NewSection.jsx` بسازید که یک `<section className="container …">` برمی‌گرداند.
2. آن را در `App.jsx` ایمپورت کنید و در جای دلخواه داخل `<main>` بگذارید.
3. استایلش را با یک کامنت عنوان به انتهای `styles.css` اضافه کنید.
4. اگر انیمیشن ظاهر شدن می‌خواهد، کلاسش را به `revealSel` اضافه کنید.
